# ETL и автоматизация подготовки данных

**Автор:** Ильнур Аскаров, когорта 49.

## Что реализовано

- Начальная загрузка отчёта и ежедневных инкрементов через API.
- Миграция схемы и поддержка старых данных без статуса заказа.
- Учёт продаж и возвратов в `mart.f_sales`: возвраты уменьшают выручку.
- Расчёт недельной витрины `mart.f_customer_retention`.
- Повторная загрузка без дубликатов и восстановление неполных данных.

## Структура

- `src/dags/sprint3.py` — DAG Airflow.
- `src/dags/order_utils.py` — проверка и нормализация CSV.
- `src/dags/sql/` — миграция и SQL загрузки витрин.
- `tests/` — автоматические и интеграционные проверки.

## Запуск

1. Запустить Docker-тренажёр из задания.
2. Скопировать содержимое `src/dags/` в `/lessons/dags/`.
3. Настроить подключения Airflow `postgresql_de` и `http_conn_id`.
   В Extra HTTP-подключения указать `api_key`.
4. Создать Variable `project3_nickname` со значением `ilnur_askarov`.
   При наличии готового отчёта указать `project3_report_id`.
5. Запустить DAG за даты доступных инкрементов:

```bash
airflow dags backfill sales_mart_project3 -s 2026-10-27 -e 2026-11-01
````
Основной отчёт загружается автоматически перед первым инкрементом.
Данные дня заменяются целиком, после чего пересчитывается его неделя.
Идентификатор недели содержит ISO-год и номер недели.
Пройдены 20 автоматических тестов. В учебном Airflow/PostgreSQL проверены
загрузка данных, отрицательные суммы возвратов, согласованность витрин,
повторный запуск и восстановление неполного инкремента без дубликатов.
